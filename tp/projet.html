Projet – Une application multiplateforme

React Native · En trinôme · Du 27 octobre au 17 décembre

En trinôme, vous concevez une application React Native sur le sujet de votre choix. Elle fonctionne avec le même code dans un navigateur de bureau et sur un téléphone. Le projet avance à chaque TP : chaque TP est un jalon du projet final.

Le projet en bref

  • Sujet libre, validé par moi avant le TP2.

  • Chaque membre est propriétaire d'une partie, dont un CRUD Firebase.
  • Soutenance le 17 décembre. Rendu : dernier commit poussé le jeudi 17 décembre avant 23h59.

1 Ce que l'application doit contenir

Obligatoire

  • Au moins 4 écrans, organisés avec Expo Router : des onglets, une pile et au moins une route dynamique (par exemple /items/[id]).
  • Sur le web, l'URL suit la navigation : une page de détail s'ouvre directement depuis son adresse.
  • Un catalogue responsive : une grille sur ordinateur, une liste fluide sur téléphone, avec des filtres dont la logique vit dans un hook.
  • Une API publique consommée avec fetch(), avec les états de chargement et d'erreur.
  • Firebase : authentification par e-mail et trois CRUD (créer, lire, modifier, supprimer) sur trois collections différentes, un par partie.
  • Une architecture MVC en TypeScript : modèles typés, services, hooks contrôleurs, composants d'affichage purs.
  • Une interface lisible et cohérente : hiérarchie visuelle, contrastes suffisants, retours visuels au toucher.
  • Une version web déployée en ligne (GitHub Pages ou équivalent), à jour du dernier commit.
  • Un README.md complet et exécutable : en suivant ses instructions sur un poste neuf, le projet se lance sans autre manipulation (voir la partie 5).
Une application qui ne se lance pas sur le web ou sur Expo Go ne peut pas être évaluée. Testez les deux à chaque commit important.

Valorisé (bonus)

  • Une API native du téléphone : caméra, localisation, notifications, retour haptique…
  • Des animations soignées.
  • Un cache ou un mode hors ligne.
  • Des tests automatisés des fonctions du modèle.
  • Une bibliothèque d'état (Zustand, TanStack Query…), si vous savez expliquer ce choix.

5 Le dépôt et le rendu

  • Un dépôt GitHub privé nommé rn-projet-nom1-nom2-nom3, avec Chris-CHEVALIER invité dès le premier jour.
  • Chacun commite avec son propre compte, régulièrement.
  • Une branche par fonctionnalité (GitHub Flow) : une pull request relue par un autre membre, puis fusionnée dans main une fois testée. Le rendu final est la branche main.
  • Le projet se lance avec npm install puis npm start, sans autre manipulation que celles du README. Aucun fichier APK ou IPA n'est demandé.

Le README contient

  • le sujet, les membres du groupe (prénom, nom, compte GitHub) et le propriétaire de chaque partie ;
  • le lien de la version web déployée ;
  • les fonctionnalités, avec des captures d'écran sur le web et sur mobile ;
  • l'API publique utilisée et le schéma des trois collections Firebase ;
  • le parcours de navigation (la liste des écrans et leurs URL) ;
  • les instructions de lancement, dont la configuration Firebase à fournir. Je les suis à la lettre sur un poste neuf ;
  • les bonus réalisés ;
  • la déclaration d'usage de l'IA.
Rendu final Rien à envoyer : votre invitation me donne accès au dépôt. Je corrige le dernier commit poussé sur main le jeudi 17 décembre avant 23h59.

6 L'évaluation

Votre note de projet est la moyenne de deux notes sur 20 : la production du groupe et votre soutenance. Elle compte pour 50 % de la note du module, l'examen écrit pour les 50 % restants.

Chaque critère vaut 1 point : il est rempli ou il ne l'est pas. Je vérifie une partie des critères automatiquement à partir de votre dépôt, le reste sur votre version web déployée et sur Expo Go.

Un CRUD est complet s'il permet de créer, lire, modifier et supprimer, et si chaque utilisateur ne voit que ses propres données. Un critère de fonctionnalité doit marcher sur le web et sur mobile.

7 L'IA générative

  • L'IA (ChatGPT, Claude, Copilot…) est autorisée pour le projet.
  • Chaque membre doit comprendre et savoir expliquer chaque partie du code. Une fonctionnalité que personne ne sait expliquer pendant la soutenance n'est pas comptée.
  • Déclarez votre usage dans le README : quels outils, pour quelles tâches.
  • Méfiez-vous des réponses qui datent : expo eject, expo-cli global ou React Navigation configuré à la main ne correspondent pas à la version d'Expo utilisée dans ce module.
