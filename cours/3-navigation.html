Deux logiques à réconcilier

Sur le webSur mobile

Avec Expo Router, chaque écran a une URL. La même navigation produit une pile sur mobile et des adresses dans le navigateur.

La pile d'écrans

Expo Router s'appuie sur React Navigation, la bibliothèque de navigation de référence. Vous n'avez pas à la configurer vous-mêmes.
02

Expo Router : les fichiers sont les routes

Le routage par fichiers

Un fichier, une URL


src/app/
├── _layout.tsx         pile racine
├── +not-found.tsx      URL inconnue
├── (tabs)/
│   ├── _layout.tsx     onglets
│   ├── index.tsx       /
│   └── favorites.tsx   /favorites
└── stays/
    └── [id].tsx        /stays/s1, /stays/s2…
  • Un nom ordinaire devient un morceau d'URL. _ : le fichier n'est pas une route. _layout.tsx est le navigateur de son dossier
  • ( ) : un groupe, absent de l'URL. (tabs)/favorites.tsx répond à /favorites
  • [ ] : un segment dynamique, récupéré comme paramètre (id vaut s3)
  • + : une route spéciale d'Expo Router. +not-found répond aux adresses inconnues
Projet de démo : demos/cours3. Ouvrir /_sitemap dans le navigateur pour voir toutes les routes générées.

Préparer le projet


npx expo install @expo/vector-icons
mkdir "src/app/(tabs)"
mv src/app/index.tsx "src/app/(tabs)/"
  • Les icônes des onglets viennent de @expo/vector-icons. npx expo install choisit la version compatible avec le SDK
  • Le catalogue devient le premier onglet : on le range dans le groupe (tabs)
On part du projet obtenu à la fin du cours précédent. Le catalogue garde son code : seul son dossier change.

Charger un seul séjour

import { Stay, StayType } from "@/models/stay";

const SITE = "https://chris-chevalier.github.io/react-native-supports";
const STAYS_URL = `${SITE}/api/stays.json`;

// Forme de la réponse de l'API, limitée à ce qu'on utilise
type StayResponse = {
  id: string;
  title: string;
  type: StayType;
  price_per_night: number;
  is_available: boolean;
  image_url: string | null;
  location: { city: string; latitude: number; longitude: number };
};

// Traduit une réponse de l'API dans le vocabulaire du modèle
function toStay(response: StayResponse): Stay {
  return {
    id: response.id,
    title: response.title,
    city: response.location.city,
    type: response.type,
    pricePerNight: response.price_per_night,
    available: response.is_available,
    latitude: response.location.latitude,
    longitude: response.location.longitude,
    imageUrl: response.image_url ?? undefined,
  };
}

export async function fetchStays(): Promise<Stay[]> {
  const response = await fetch(STAYS_URL);
  if (!response.ok) throw new Error(`Erreur HTTP ${response.status}`);
  const data: StayResponse[] = await response.json();
  return data.map(toStay);
}

export async function fetchStay(
  id: string,
): Promise<Stay | undefined> {
  const stays = await fetchStays();
  return stays.find((stay) => stay.id === id);
}
  • Seule la dernière fonction, fetchStay, est nouvelle : elle est surlignée. Le reste du fichier existe déjà
  • Le détail ne reçoit qu'un identifiant : le service retrouve le séjour
  • Il renvoie undefined si l'identifiant est inconnu. L'écran devra le prévoir

Le hook useStay

import { useEffect, useState } from "react";

import { Stay } from "@/models/stay";
import { fetchStay } from "@/services/stays-service";

export type StayState =
  | { status: "loading" }
  | { status: "not-found" }
  | { status: "success"; stay: Stay };

export function useStay(id: string) {
  const [state, setState] = useState<StayState>({
    status: "loading",
  });

  useEffect(() => {
    let cancelled = false;
    fetchStay(id).then((stay) => {
      if (!cancelled)
        setState(
          stay
            ? { status: "success", stay }
            : { status: "not-found" },
        );
    });
    return () => {
      cancelled = true;
    };
  }, [id]);

  return state;
}
  • Trois états : chargement, introuvable, succès
  • id est une dépendance de l'effet : changer de séjour recharge les données

Une route dynamique

import { Stack, useLocalSearchParams } from "expo-router";
import {
  Image,
  ScrollView,
  StyleSheet,
  Text,
  View,
} from "react-native";

import { StateMessage } from "@/components/state-message";
import { useStay } from "@/hooks/use-stay";
import { Stay } from "@/models/stay";

export default function StayScreen() {
  const { id } = useLocalSearchParams<{ id: string }>();
  const state = useStay(id);

  if (state.status === "loading") return <StateMessage loading />;
  if (state.status === "not-found")
    return <StateMessage message="Ce séjour est introuvable." />;
  return <StayDetails stay={state.stay} />;
}

function StayDetails({ stay }: { stay: Stay }) {
  return (
    <ScrollView contentContainerStyle={styles.content}>
      <Stack.Screen options={{ title: stay.title }} />
      <Image source={{ uri: stay.imageUrl }} style={styles.image} />
      <View style={styles.body}>
        <Text style={styles.title}>{stay.title}</Text>
        <Text style={styles.city}>
          {stay.city} · {stay.pricePerNight} € / nuit
        </Text>
      </View>
    </ScrollView>
  );
}

const styles = StyleSheet.create({
  content: { width: "100%", maxWidth: 800, alignSelf: "center" },
  image: { width: "100%", aspectRatio: 16 / 9 },
  body: { padding: 16, gap: 8 },
  title: { fontSize: 26, fontWeight: "800" },

  • useLocalSearchParams lit id dans l'URL
  • L'écran ne reçoit que l'identifiant, jamais l'objet entier : il recharge ses données. C'est ce qui permet d'ouvrir la page depuis un lien
  • <Stack.Screen options> change le titre de l'en-tête
  • Un identifiant inconnu est un cas prévu
StayDetails est une vue pure : elle reçoit un séjour déjà chargé, ce qui évite de tester state.status dans tout le JSX.

URL et liens profonds

Sur le web

  • L'URL /stays/s3 s'affiche dans la barre d'adresse
  • On peut la copier, la partager, la recharger : le même écran s'ouvre
  • Le bouton retour du navigateur dépile

Sur mobile

  • Le scheme d'app.json définit le préfixe : staybnb://stays/s3

Quiz

Quelle URL correspond au fichier src/app/(tabs)/favorites.tsx ?

/favorites : les groupes entre parenthèses n'apparaissent pas dans l'URL.

Pourquoi passer l'identifiant du séjour au détail plutôt que l'objet complet ?

L'URL doit suffire à afficher la page : ouverte depuis un lien ou rechargée, elle n'a que l'identifiant. Le détail recharge donc ses données.

Le cycle de vie

Écrans et application

Un écran ne se démonte pas toujours

import { Link, useFocusEffect } from "expo-router";
import { useCallback } from "react";
import { FlatList, StyleSheet, Text } from "react-native";

import { StateMessage } from "@/components/state-message";
import { useFavorites } from "@/hooks/use-favorites";
import { useStays } from "@/hooks/use-stays";

export default function FavoritesScreen() {
  const { state, reload } = useStays();
  const { isFavorite } = useFavorites();

  // À chaque fois que l'onglet redevient visible, on recharge les
  // séjours
  useFocusEffect(
    useCallback(() => {
      reload();
    }, [reload]),
  );

  if (state.status !== "success")
    return <StateMessage loading={state.status === "loading"} />;
  const favoriteStays = state.stays.filter((stay) =>
    isFavorite(stay.id),
  );

  return (
    <FlatList
      data={favoriteStays}
      keyExtractor={(stay) => stay.id}
      renderItem={({ item }) => (
        <Link
          href={{ pathname: "/stays/[id]", params: { id: item.id } }}
          style={styles.item}
        >
          {item.title}
        </Link>
      )}
      ListEmptyComponent={
        <Text style={styles.item}>Aucun favori pour le moment.</Text>
      }
      contentContainerStyle={styles.list}
    />
  );
}

const styles = StyleSheet.create({
  list: { padding: 16 },
  item: { fontSize: 17, paddingVertical: 8 },
});
  • Un onglet quitté reste monté : son useEffect(…, []) ne s'exécutera plus
  • useFocusEffect (d'expo-router) s'exécute à chaque affichage de l'écran
  • La fonction renvoyée, si vous en écrivez une, s'exécute quand l'écran perd le focus
  • useCallback évite de relancer l'effet à chaque rendu

L'application revient au premier plan

import { useEffect } from "react";
import { AppState } from "react-native";

// Appelle onForeground chaque fois que l'application revient au
// premier plan
export function useOnForeground(onForeground: () => void) {
  useEffect(() => {
    const subscription = AppState.addEventListener(
      "change",
      (status) => {
        if (status === "active") onForeground();
      },
    );
    // Au démontage, on retire l'écouteur
    return () => subscription.remove();
  }, [onForeground]);
}
  • AppState signale le premier plan ("active") et l'arrière-plan ("background"). Sur le web, il suit la visibilité de l'onglet du navigateur
  • Le hook reçoit une fonction à appeler au retour dans l'application
  • Toujours retirer l'écouteur au démontage, sinon il s'accumule

Recharger le catalogue au retour

      <FlatList
        key={columns}
        numColumns={columns}
        data={visibleStays}

  );
}

Les listes volumineuses

FlatList et SectionList

SectionList : regrouper dans le modèle

export type StayType = "apartment" | "house" | "cabin";

export type Stay = {
  id: string;
  title: string;
  city: string;
  type: StayType;
  pricePerNight: number;
  available: boolean;
  latitude: number;
  longitude: number;
  imageUrl?: string;
};

export type StayFilters = {
  query: string;
  type: StayType | null;
  onlyAvailable: boolean;
};

export const STAY_TYPE_LABELS: Record<StayType, string> = {
  apartment: "Appartement",
  house: "Maison",
  cabin: "Cabane",
};

// Règle métier : une fonction pure, sans React, facile à tester
export function matchesFilters(
  stay: Stay,
  filters: StayFilters,
): boolean {
  const search = filters.query.trim().toLowerCase();
  const matchesQuery =
    stay.title.toLowerCase().includes(search) ||
    stay.city.toLowerCase().includes(search);
  const matchesType =
    filters.type === null || stay.type === filters.type;
  const matchesAvailability =
    !filters.onlyAvailable || stay.available;
  return matchesQuery && matchesType && matchesAvailability;
}

export type CitySection = { title: string; data: Stay[] };

// Regroupe des séjours par ville, au format attendu par SectionList
export function groupByCity(stays: Stay[]): CitySection[] {
  const cities = [...new Set(stays.map((stay) => stay.city))].sort();
  return cities.map((city) => ({
    title: city,
    data: stays.filter((stay) => stay.city === city),
  }));
}
  • Chaque section a un title et un tableau data
  • Le regroupement est une règle du modèle, pure et testable

SectionList : afficher les groupes

import { Link, useFocusEffect } from "expo-router";
import { useCallback } from "react";
import { SectionList, StyleSheet, Text } from "react-native";

import { StateMessage } from "@/components/state-message";
import { useFavorites } from "@/hooks/use-favorites";
import { useStays } from "@/hooks/use-stays";
import { groupByCity } from "@/models/stay";

export default function FavoritesScreen() {
  const { state, reload } = useStays();
  const { isFavorite } = useFavorites();

  // À chaque fois que l'onglet redevient visible, on recharge les
  // séjours
  useFocusEffect(
    useCallback(() => {
      reload();
    }, [reload]),
  );

  if (state.status !== "success")
    return <StateMessage loading={state.status === "loading"} />;
  const sections = groupByCity(
    state.stays.filter((stay) => isFavorite(stay.id)),
  );

  return (
    <SectionList
      sections={sections}
      keyExtractor={(stay) => stay.id}
      renderSectionHeader={({ section }) => (
        <Text style={styles.city}>{section.title}</Text>
      )}
      renderItem={({ item }) => (
        <Link
          href={{ pathname: "/stays/[id]", params: { id: item.id } }}
          style={styles.item}
        >
          {item.title}
        </Link>
      )}
      ListEmptyComponent={
        <Text style={styles.item}>Aucun favori pour le moment.</Text>
      }
      contentContainerStyle={styles.list}
    />
  );
}

const styles = StyleSheet.create({
  list: { padding: 16 },
  city: {
    fontSize: 14,
    fontWeight: "700",
    textTransform: "uppercase",
    color: "#0B7A70",
    marginTop: 16,
  },
  item: { fontSize: 17, paddingVertical: 8 },
});
  • SectionList est un composant de base, comme FlatList : sections remplace son data
  • renderSectionHeader affiche le titre de chaque groupe, renderItem chaque élément
  • Une liste longue reste fluide si chaque élément a une clé stable (keyExtractor) et si le tri est fait avant, dans le modèle ou le hook. Au-delà de quelques milliers de lignes : FlashList

Quiz

L'onglet « Favoris » charge ses données dans un useEffect(…, []). J'ajoute un favori depuis le catalogue puis je reviens. Que se passe-t-il ?

L'onglet n'est pas rechargé : il est resté monté, l'effet ne se relance pas. Il faut useFocusEffect.

fetch reçoit une réponse 404. Le bloc catch s'exécute-t-il ?

Non : fetch ne lève une erreur qu'en cas d'échec réseau. Il faut tester response.ok et lever l'erreur soi-même.

À retenir

  • Avec Expo Router, chaque fichier de src/app/ est une route et chaque écran a une URL
  • _layout.tsx choisit le navigateur : pile (Stack) ou onglets (Tabs depuis expo-router/js-tabs)
  • Une route dynamique reçoit un identifiant et recharge ses données
  • Un service appelle l'API avec fetch, teste response.ok et traduit la réponse en modèle
  • useFocusEffect pour un écran qui redevient visible, AppState pour l'application
  • Des listes légères, filtrées en amont. SectionList pour des groupes
