01

De React à React Native

Ce que vous savez déjà, ce qui change

React et React Native

React

  • Une bibliothèque JavaScript créée par Meta (ex-Facebook), open source depuis 2013
  • Elle construit des interfaces web à partir de composants
  • Facebook, Instagram, Netflix ou Airbnb l'utilisent sur le web

React Native

  • Un framework créé par Meta, open source depuis 2015
  • Il reprend React pour créer de vraies applications mobiles iOS et Android, avec un seul code
  • Instagram, Discord, Shopify ou Microsoft Office l'utilisent : voir la vitrine officielle
React décrit l'interface. Le moteur de rendu l'affiche : le DOM du navigateur pour React, les vues natives du téléphone pour React Native.

Le même modèle, une autre cible

React (web)React Native
Ce que vous écrivezDes composants, des props, de l'état, des hooks
Les composants de base<div>, <span>, <img>, <input>View, Text, Image, TextInput
Les stylesCSS, cascade, sélecteursObjets JavaScript, aucune cascade*
Le renduLe DOM du navigateurDes vues natives iOS et Android
La navigationDes URLUne pile d'écrans

* Aucune cascade : un style ne s'applique qu'au composant qui le reçoit. Une couleur donnée à un conteneur ne colore pas le texte qu'il contient. Seul un <Text> transmet son style à un <Text> enfant.

Votre logique React se réutilise telle quelle. Ce qui change, ce sont les composants de base et les contraintes du mobile.

Comment JavaScript devient une vue native

1. Votre code
Vos composants TypeScript sont exécutés par Hermes, le moteur JavaScript optimisé pour le mobile
2. Le rendu
React calcule l'arbre des composants. Le moteur de rendu Fabric le traduit en vues natives
3. L'écran
iOS affiche une UIView, Android une android.view.View, le navigateur une <div>

La nouvelle architecture

JSI (JavaScript Interface) permet des appels directs entre JavaScript et le natif. C'est l'architecture par défaut des projets actuels.
Hermes : moteur JavaScript de Meta, compile en bytecode à la construction. Fabric : nouveau moteur de rendu. TurboModules : modules natifs chargés à la demande via JSI. La nouvelle architecture est activée par défaut depuis React Native 0.76. Le message à retenir : il n'y a plus de pont asynchrone entre JS et natif.

React Native for Web

import { useState } from "react";

    borderRadius: 8,

  • <View> devient une <div>, <TextInput> un <input>
  • StyleSheet génère des classes CSS optimisées
  • Un seul code pour trois plateformes

<div class="css-view-…">
  <input placeholder="Votre prénom"
    class="css-textinput-… r-borderWidth-…">
  <div dir="auto" class="css-text-…">…</div>
</div>
Démo : ouvrir la version web de l'application d'exemple et inspecter le DOM avec les outils de développement.

Quiz

Une application React Native peut-elle utiliser <div> ?

Non. <div> n'existe que dans le DOM : l'application planterait sur iOS et Android. Utilisez <View>, que React Native for Web transforme en <div> dans le navigateur.

Une application React Native est-elle une page web dans une application ?

Non. Sur mobile, ce sont de vraies vues natives. Une page web affichée dans une application s'appelle une WebView (c'est l'approche de Cordova ou d'Ionic).

Expo et TypeScript

Créer et lancer un projet

Expo : créer et lancer le projet


npx create-expo-app@latest mon-app
cd mon-app
npm run reset-project
npx expo start
  • Expo est le framework recommandé par l'équipe de React Native
  • npm run reset-project retire l'application d'exemple pour partir d'un écran vierge. À sa question, répondez n : l'exemple est supprimé au lieu d'être déplacé
  • w ouvre la version web, i le simulateur iOS (macOS et Xcode), a l'émulateur Android. Le QR code s'ouvre avec Expo Go sur votre téléphone
  • Chaque sauvegarde met l'écran à jour (Fast Refresh)
Indispensable pour le web. Dans app.json, remplacez "output": "server" par "output": "single". Avec "server", la page est préparée à l'avance, sans connaître la taille de la fenêtre. Un écran qui s'adapte à la largeur plante alors au chargement. Ce plantage s'appelle une erreur d'hydratation : le premier affichage calculé par le navigateur ne correspond pas à la page reçue.
Le téléphone et l'ordinateur doivent être sur le même réseau. Si le Wi-Fi de l'école bloque la connexion, lancez npx expo start --tunnel.
Les dossiers ios/ et android/ sont générés à la demande : on ne les écrit jamais à la main. Hydratation : React rattache ses événements au HTML reçu du serveur ; si le premier rendu diffère, il échoue.

L'arborescence du projet


src/
├── app/              écrans et navigation (Expo Router)
│   ├── _layout.tsx   navigateur racine
│   └── index.tsx     écran de l'URL « / »
├── components/       composants réutilisables
├── hooks/            hooks personnalisés
├── models/           types des données
└── data/             données locales
assets/               images, polices
app.json              configuration Expo
tsconfig.json         configuration TypeScript
  • Ce n'est pas l'arborescence créée par Expo : après reset-project, src/ ne contient que app/. Les autres dossiers suivent les bonnes pratiques : un dossier par rôle
  • Chaque fichier de src/app/ est un écran. Son chemin donne son URL
  • Tout le reste du code vit en dehors de src/app/
  • 💡 L'alias @/ pointe vers src/ : import { STAYS } from "@/data/stays"
Les dossiers models, data et hooks n'existent pas après reset-project : on les crée au fil des exemples.

Composants, styles et responsive

Les composants de base de toute interface

Les composants de base

React Native fournit un petit jeu de composants de base (core components). Toute interface s'écrit avec eux.

ComposantRôleÉquivalent web
ViewConteneur et mise en page<div>
TextTout texte affiché<p>, <span>
ImageImage locale ou distante<img>
TextInputSaisie de texte<input>
PressableZone qui réagit au toucher<button>
ScrollViewContenu qui défile (court)overflow: auto
FlatListListe longue, affichée au fur et à mesureAucun

Tous s'importent depuis react-native : import { View, Text } from "react-native";

View et Text

import { StyleSheet, Text } from "react-native";

type GreetingProps = { firstName: string; unread?: number };

export function Greeting({ firstName, unread = 0 }: GreetingProps) {
  return (
    <Text style={styles.greeting}>
      Bonjour <Text style={styles.bold}>{firstName}</Text>
      {unread > 0 && ` · ${unread} message(s)`}
    </Text>
  );
}

const styles = StyleSheet.create({
  greeting: { fontSize: 18 },
  bold: { fontWeight: "700" },
});
  • Tout texte doit être dans un <Text>. Un texte posé dans une <View> fait planter l'application
  • Un <Text> peut contenir d'autres <Text>. Ce sont les seuls à hériter du style de leur parent
  • Dans un écran : <Greeting firstName="Manon" unread={3} />. Sans firstName, TypeScript refuse l'appel
  • Export nommé pour un composant : import { Greeting } from "@/components/greeting". Seuls les écrans de src/app/ utilisent export default, exigé par Expo Router

Image

import { Image, StyleSheet, View } from "react-native";

type ImageExamplesProps = { imageUrl: string };

export function ImageExamples({ imageUrl }: ImageExamplesProps) {
  return (
    <View style={styles.container}>
      {/* Image locale, intégrée à l'application */}
      <Image
        source={require("@/assets/images/icon.png")}
        style={styles.logo}
      />
      {/* Image distante, téléchargée à l'affichage */}
      <Image source={{ uri: imageUrl }} style={styles.photo} />
    </View>
  );
}

const styles = StyleSheet.create({
  container: { gap: 16 },
  logo: { width: 64, height: 64 },
  photo: { width: "100%", aspectRatio: 4 / 3, borderRadius: 12 },
});
  • Une image locale passe par require() : elle est intégrée à l'application au moment du build
  • Une image distante n'a pas de taille par défaut : sans largeur ni hauteur, elle reste invisible
  • aspectRatio: 4 / 3 : la hauteur vaut les trois quarts de la largeur, le format d'une photo classique. Avec width: "100%", l'image prend toute la largeur et sa hauteur suit
  • Dans le JSX, un commentaire s'écrit {/* … */}. Un // y deviendrait du texte, ce qui fait planter l'application

Un retour visuel au toucher

import {
  Image,
  Pressable,
  StyleSheet,
  Text,
  View,
} from "react-native";

import { Stay } from "@/models/stay";

type StayCardProps = {
  stay: Stay;
  isFavorite: boolean;
  onToggleFavorite: (id: string) => void;
};

const formatPrice = (price: number) =>
  new Intl.NumberFormat("fr-FR", {
    style: "currency",
    currency: "EUR",
    maximumFractionDigits: 0,
  }).format(price);

export function StayCard({
  stay,
  isFavorite,
  onToggleFavorite,
}: StayCardProps) {
  return (
    <View style={styles.card}>
      <Image source={{ uri: stay.imageUrl }} style={styles.image} />
      <View style={styles.body}>
        <Text style={styles.title}>{stay.title}</Text>
        <Text style={styles.city}>{stay.city}</Text>
        <Text style={styles.price}>
          {formatPrice(stay.pricePerNight)} / nuit
        </Text>
        {!stay.available && (
          <Text style={styles.unavailable}>Complet</Text>
        )}
        <Pressable
          onPress={() => onToggleFavorite(stay.id)}
          style={({ pressed }) => [
            styles.button,
            pressed && styles.buttonPressed,
          ]}
        >
          <Text style={styles.buttonLabel}>
            {isFavorite ? "★ Favori" : "☆ Ajouter aux favoris"}
          </Text>
        </Pressable>
      </View>
    </View>
  );
}

  • Un tableau de styles applique les suivants par-dessus les premiers. false est ignoré

Quiz

Je place trois <Text> dans une <View> sans style. Comment s'affichent-ils ?

En colonne, l'un sous l'autre : flexDirection vaut column par défaut.

Je donne color: "red" à une <View>. Le texte qu'elle contient devient-il rouge ?

Non. Il n'y a pas de cascade : seul un <Text> parent transmet son style à un <Text> enfant.

Afficher une liste : FlatList

import { useState } from "react";
import {
  FlatList,
  StyleSheet,
  Text,
  TextInput,
  View,
} from "react-native";

import { StayCard } from "@/components/stay-card";
import { STAYS } from "@/data/stays";

export default function CatalogScreen() {
  const [query, setQuery] = useState("");
  const [favorites, setFavorites] = useState<string[]>([]);

  const toggleFavorite = (id: string) =>
    setFavorites((current) =>
      current.includes(id)
        ? current.filter((f) => f !== id)
        : [...current, id],
    );

  const search = query.trim().toLowerCase();
  const visibleStays = STAYS.filter(
    (stay) =>
      stay.title.toLowerCase().includes(search) ||
      stay.city.toLowerCase().includes(search),
  );

  return (
    <View style={styles.screen}>
      <View style={styles.container}>
        <Text style={styles.heading}>
          Séjours · {favorites.length} favori(s)
        </Text>
        <TextInput
          value={query}
          onChangeText={setQuery}
          placeholder="Rechercher une ville ou un logement"
          style={styles.search}
        />
        <FlatList
          data={visibleStays}
          keyExtractor={(stay) => stay.id}
          renderItem={({ item }) => (
            <StayCard
              stay={item}
              isFavorite={favorites.includes(item.id)}
              onToggleFavorite={toggleFavorite}
            />
          )}
          ListEmptyComponent={
            <Text style={styles.empty}>
              Aucun logement ne correspond.
            </Text>
          }
        />
      </View>
    </View>
  );
}

const styles = StyleSheet.create({
  screen: { flex: 1, backgroundColor: "#F2F3F9" },
  container: {
    flex: 1,
    width: "100%",
    maxWidth: 1100,
    alignSelf: "center",
    padding: 8,
  },
  heading: { fontSize: 24, fontWeight: "800", margin: 8 },
  search: {
    margin: 8,
    padding: 12,
    borderRadius: 8,
    borderWidth: 1,
    borderColor: "#D9DCEA",
    backgroundColor: "#fff",
    fontSize: 16,
  },
  empty: { margin: 8, fontSize: 16 },
});
  • 1. Les favoris sont un état : toggleFavorite ajoute ou retire un identifiant
  • 2. visibleStays se calcule à partir de la recherche : ce n'est pas un état
  • 3. FlatList ne crée que les cartes visibles à l'écran, puis les suivantes au fil du défilement. Une liste de 1 000 séjours reste donc fluide
  • keyExtractor joue le rôle de la prop key de map()
  • ScrollView affiche tout d'un coup : réservez-la aux contenus courts
Les listes volumineuses (SectionList, optimisations) sont au programme du cours 3.

Pas de media queries : un hook

import { useWindowDimensions } from "react-native";

// Nombre de colonnes selon la largeur de la fenêtre (points de
// rupture)
export function useColumns(): number {
  const { width } = useWindowDimensions();
  if (width >= 1024) return 3;
  if (width >= 600) return 2;
  return 1;
}
  • StyleSheet ne connaît pas les media queries du CSS
  • useWindowDimensions() renvoie la taille de la fenêtre et déclenche un nouveau rendu quand elle change (rotation, redimensionnement)
  • Ce n'est pas qu'une question de web : une tablette, un téléphone pliable (Galaxy Z Fold) ou à deux écrans (Surface Duo) change de largeur pendant l'utilisation
  • L'ancienne API Dimensions.get() ne se met pas à jour toute seule : préférez le hook

export default function CatalogScreen() {
  const columns = useColumns();
  const [query, setQuery] = useState("");
  const [favorites, setFavorites] = useState<string[]>([]);

  const toggleFavorite = (id: string) =>
    setFavorites((current) =>
      current.includes(id)
        ? current.filter((f) => f !== id)
        : [...current, id],
    );

  const search = query.trim().toLowerCase();
  const visibleStays = STAYS.filter(
    (stay) =>
      stay.title.toLowerCase().includes(search) ||
      stay.city.toLowerCase().includes(search),
  );

  return (
    <View style={styles.screen}>
      <View style={styles.container}>
        <Text style={styles.heading}>
          Séjours · {favorites.length} favori(s)
        </Text>
        <TextInput
          value={query}
          onChangeText={setQuery}
          placeholder="Rechercher une ville ou un logement"
          style={styles.search}
        />
        <FlatList
          key={columns}
          data={visibleStays}
          numColumns={columns}
          keyExtractor={(stay) => stay.id}
          renderItem={({ item }) => (
            <StayCard
              stay={item}
              isFavorite={favorites.includes(item.id)}
              onToggleFavorite={toggleFavorite}
            />
          )}
          ListEmptyComponent={
            <Text style={styles.empty}>
              Aucun logement ne correspond.
            </Text>
          }
        />
      </View>
    </View>
  );
}

const styles = StyleSheet.create({
  screen: { flex: 1, backgroundColor: "#F2F3F9" },
  container: {
    flex: 1,
    width: "100%",
    maxWidth: 1100,
    alignSelf: "center",
    padding: 8,
  },
  heading: { fontSize: 24, fontWeight: "800", margin: 8 },
  search: {
    margin: 8,
    padding: 12,
    borderRadius: 8,
    borderWidth: 1,
    borderColor: "#D9DCEA",
    backgroundColor: "#fff",
    fontSize: 16,
  },
  empty: { margin: 8, fontSize: 16 },
});
  • numColumns transforme la liste en grille
  • FlatList refuse de changer de nombre de colonnes à chaud. Changer sa key force un nouveau montage
  • Sur le conteneur, maxWidth: 1100 et alignSelf: "center" évitent une ligne de 2 500 px sur un grand écran

À retenir

  • React Native affiche de vraies vues natives. React Native for Web les traduit en DOM
  • Expo crée, lance et teste le projet. Chaque fichier de src/app/ est un écran
  • TypeScript décrit vos données et vos props, et vérifie avant l'exécution (npx tsc --noEmit)
  • Tout texte est dans un <Text>. Les styles sont des objets, sans cascade, en colonne par défaut
  • Le responsive passe par useWindowDimensions() et des points de rupture
