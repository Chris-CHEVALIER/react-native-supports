De React à React Native

Ce que vous savez déjà, ce qui change

Le même modèle, une autre cible

React (web)React Native
Ce que vous écrivezDes composants, des props, de l'état, des hooks
Les briques<div>, <span>, <img>, <input><View>, <Text>, <Image>, <TextInput>
Les stylesCSS, cascade, sélecteursObjets JavaScript, aucune cascade
Le renduLe DOM du navigateurDes vues natives iOS et Android (et le DOM sur le web)
La navigationDes URLUne pile d'écrans (et des URL sur le web)
Votre logique React se réutilise telle quelle. Ce qui change, ce sont les briques d'affichage et les contraintes du mobile.

Comment JavaScript devient une vue native

1. Votre code
Vos composants TypeScript sont exécutés par Hermes, le moteur JavaScript optimisé pour le mobile
2. Le rendu
React calcule l'arbre des composants. Le moteur de rendu Fabric le traduit en vues natives
3. L'écran
iOS affiche une UIView, Android une android.view.View, le navigateur une <div>

Avant : le bridge

JavaScript et le natif échangeaient des messages asynchrones sérialisés en JSON. Le pont devenait un goulot d'étranglement.

Aujourd'hui : la nouvelle architecture

JSI (JavaScript Interface) permet des appels directs entre JavaScript et le natif. C'est l'architecture par défaut des projets actuels.
Hermes : moteur JavaScript de Meta, compile en bytecode à la construction. Fabric : nouveau moteur de rendu. TurboModules : modules natifs chargés à la demande via JSI. La nouvelle architecture est activée par défaut depuis React Native 0.76. Le message à retenir : il n'y a plus de pont asynchrone entre JS et natif.

React Native for Web

  • React Native for Web réimplémente les composants de React Native avec React DOM
  • <View> devient une <div>, <TextInput> un <input>
  • StyleSheet génère des classes CSS optimisées
  • Un seul code pour trois plateformes

<View style={styles.card}>
  <Text>Studio lumineux</Text>
</View>
          

<div class="css-view-g5y9jx r-…">
  <div dir="auto" class="css-text-…">
    Studio lumineux
  </div>
</div>
Démo : ouvrir la version web de l'application d'exemple et inspecter le DOM avec les outils de développement.

Quiz

Une application React Native peut-elle utiliser <div> ?

Non. <div> n'existe que dans le DOM : l'application planterait sur iOS et Android. Utilisez <View>, que React Native for Web transforme en <div> dans le navigateur.

Une application React Native est-elle une page web dans une application ?

Non. Sur mobile, ce sont de vraies vues natives. Une page web affichée dans une application s'appelle une WebView (c'est l'approche de Cordova ou d'Ionic).
02

Expo, Expo Router et TypeScript

Créer et lancer un projet

Expo : le framework recommandé

  • Expo est le framework que l'équipe de React Native recommande pour démarrer un projet
  • Il fournit une CLI (npx expo), des modules natifs (caméra, localisation, notifications…) et Expo Router pour la navigation
  • Expo Go : une application à installer sur votre téléphone pour tester votre code sans rien compiler
  • Les dossiers natifs ios/ et android/ sont générés à la demande. Vous ne les écrivez jamais à la main
Méfiez-vous des tutoriels anciens et des réponses d'IA. expo eject, expo-cli installé globalement ou « workflow managed » sont des notions disparues.

Créer et lancer le projet


npx create-expo-app@latest mon-app
cd mon-app
npm run reset-project
npx expo start

reset-project retire l'exemple fourni et laisse un projet vide.

  • Sur le web : appuyez sur w dans le terminal
  • Sur votre téléphone : scannez le QR code avec Expo Go (Android) ou l'appareil photo (iOS)
  • Sauvegardez un fichier : l'écran se met à jour aussitôt (Fast Refresh)
Le Wi-Fi de l'école bloque la connexion du téléphone ? Lancez npx expo start --tunnel.

L'arborescence du projet


src/
├── app/              écrans et navigation (Expo Router)
│   ├── _layout.tsx   navigateur racine
│   └── index.tsx     écran de l'URL « / »
├── components/       composants réutilisables
├── hooks/            hooks personnalisés
├── models/           types des données
└── data/             données locales
assets/               images, polices
app.json              configuration Expo
tsconfig.json         configuration TypeScript
  • Chaque fichier de src/app/ est un écran. Son chemin donne son URL
  • Tout le reste du code vit en dehors de src/app/
  • L'alias @/ pointe vers src/ : import { STAYS } from "@/data/stays"
Les dossiers models, data et hooks n'existent pas après reset-project : on les crée. On détaillera Expo Router au cours 3.

Un réglage pour le web : web.output

  • Le modèle actuel d'Expo rend les pages sur un serveur ("server") avant de les envoyer au navigateur
  • Le serveur ne connaît pas la taille de la fenêtre. Un écran responsive y est calculé différemment : React signale alors une erreur d'hydratation
  • Dans ce module, on produit une application (SPA) : réglez "single"

{
  "expo": {
    "web": {
      "output": "single",
      "favicon": "./assets/images/favicon.png"
    }
  }
}
Hydratation : React rattache ses événements au HTML reçu du serveur. Si le HTML ne correspond pas au premier rendu dans le navigateur, l'hydratation échoue.
J'ai rencontré l'erreur en préparant le cours : useWindowDimensions renvoie une largeur différente côté serveur. "single" est aussi la valeur par défaut d'Expo quand le champ est absent.

TypeScript : ce qui nous servira


export type StayType = "apartment" | "house" | "cabin";

export type Stay = {
  id: string;
  title: string;
  city: string;
  type: StayType;
  pricePerNight: number;
  available: boolean;
  imageUrl?: string;
};
  • type décrit la forme d'une donnée
  • "apartment" | "house" : une union, seules ces valeurs sont acceptées
  • imageUrl? : propriété facultative (string | undefined)
  • TypeScript vérifie dans l'éditeur et avec npx tsc --noEmit, avant l'exécution
Faire le lien avec le test de positionnement. Pas de génériques avancés dans ce module : types de données, props, paramètres de route et réponses d'API suffisent.

Les composants primitifs

Les briques de toute interface

Tous s'importent depuis react-native : import { View, Text } from "react-native";

View et Text


type GreetingProps = { firstName: string; unread?: number };

function Greeting({ firstName, unread = 0 }: GreetingProps) {
  return (
    <Text style={styles.greeting}>
      Bonjour <Text style={styles.bold}>{firstName}</Text>
      {unread > 0 && ` · ${unread} message(s)`}
    </Text>
  );
}

<Greeting firstName="Manon" unread={3} />
  • Tout texte doit être dans un <Text>. Un texte posé dans une <View> fait planter l'application
  • Un <Text> peut contenir d'autres <Text>. Ce sont les seuls à hériter du style de leur parent
  • Les props sont typées : <Greeting /> sans firstName est refusé par TypeScript

Image


// Image locale : intégrée à l'application
<Image
  source={require("@/assets/images/icon.png")}
  style={{ width: 64, height: 64 }}
/>

// Image distante : téléchargée à l'affichage
<Image
  source={{ uri: stay.imageUrl }}
  style={{ width: "100%", aspectRatio: 4 / 3 }}
/>
  • Une image distante n'a pas de taille par défaut. Sans largeur ni hauteur, elle reste invisible
  • aspectRatio fixe la hauteur à partir de la largeur
  • Pour des besoins avancés (cache, transitions), Expo propose expo-image

TextInput : un champ contrôlé


function NameForm() {
  const [name, setName] = useState("");
  return (
    <View style={styles.row}>
      <TextInput
        value={name}
        onChangeText={setName}
        placeholder="Votre prénom"
        style={styles.input}
      />
      <Text>{name ? `Bonjour ${name} !` : "…"}</Text>
    </View>
  );
}
  • Même principe qu'en React : l'état est la source de vérité
  • onChangeText reçoit directement le texte, sans objet événement
  • Props utiles : keyboardType, secureTextEntry, autoCapitalize

Pressable et le cycle de vie


function Counter() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    console.log("Counter affiché");
    return () => console.log("Counter retiré");
  }, []);

  return (
    <Pressable onPress={() => setCount((c) => c + 1)}>
      <Text>Appuyé {count} fois</Text>
    </Pressable>
  );
}
  • onPress remplace onClick
  • Un composant est monté, mis à jour à chaque changement d'état, puis démonté
  • useEffect(…, []) s'exécute après le premier affichage. La fonction renvoyée s'exécute au démontage
En développement, React monte deux fois les composants (Strict Mode) : le message peut apparaître deux fois. Le cycle de vie des écrans (focus, arrière-plan) arrive au cours 3.

Un retour visuel au toucher


<Pressable
  onPress={() => onToggleFavorite(stay.id)}
  style={({ pressed }) => [
    styles.button,
    pressed && styles.buttonPressed,
  ]}
>
  <Text style={styles.buttonLabel}>
    {isFavorite ? "★ Favori" : "☆ Ajouter aux favoris"}
  </Text>
</Pressable>
  • Sur mobile, il n'y a pas de survol. L'utilisateur doit voir que son doigt a été pris en compte
  • style accepte une fonction qui reçoit { pressed }
  • Un tableau de styles applique les suivants par-dessus les premiers. false est ignoré

Afficher une liste : FlatList


<FlatList
  data={visibleStays}
  keyExtractor={(stay) => stay.id}
  renderItem={({ item }) => (
    <StayCard
      stay={item}
      isFavorite={favorites.includes(item.id)}
      onToggleFavorite={toggleFavorite}
    />
  )}
  ListEmptyComponent={<Text>Aucun résultat</Text>}
/>
  • FlatList n'affiche que les éléments visibles (virtualisation)
  • keyExtractor joue le rôle de la prop key de map()
  • ScrollView affiche tout d'un coup : réservez-la aux contenus courts
Les listes volumineuses (SectionList, optimisations) sont au programme du cours 3.

Styles et Flexbox

Du CSS sans CSS

StyleSheet


const styles = StyleSheet.create({
  card: {
    flex: 1,
    backgroundColor: "#fff",
    borderRadius: 12,
    overflow: "hidden",
    margin: 8,
  },
  title: { fontSize: 18, fontWeight: "700" },
  price: { fontSize: 16, color: "#0B7A70" },
});
  • Des propriétés CSS en camelCase : backgroundColor, borderRadius
  • Des nombres sans unité : des points indépendants de la densité de l'écran
  • Aucune cascade ni sélecteur. Chaque composant reçoit son style
  • TypeScript vérifie les noms et les valeurs

Flexbox : les différences avec le web

PropriétéWeb (CSS)React Native
displayblock par défautflex partout, toujours
flexDirectionrowcolumn
alignContentnormalflex-start
flex: 1Raccourci de flex-grow, flex-shrink et flex-basis« Prends toute la place disponible »
Les éléments s'empilent verticalement par défaut. Pour les aligner sur une ligne, écrivez flexDirection: "row".

Une hiérarchie en zones


<View style={{ flex: 1 }}>
  <View style={styles.header}>
    <Text style={styles.bold}>Titre</Text>
    <Text>Action</Text>
  </View>
  <View style={{ flex: 1 }}>{/* contenu */}</View>
</View>

header: {
  flexDirection: "row",
  justifyContent: "space-between",
  alignItems: "center",
  padding: 12,
},
  • justifyContent : alignement sur l'axe principal (vertical par défaut)
  • alignItems : alignement sur l'axe secondaire
  • gap espace les enfants sans marges
  • Une zone de titre, une zone de contenu, une zone d'actions : l'utilisateur comprend l'écran en quelques secondes

Quiz

Je place trois <Text> dans une <View> sans style. Comment s'affichent-ils ?

En colonne, l'un sous l'autre : flexDirection vaut column par défaut.

Je donne color: "red" à une <View>. Le texte qu'elle contient devient-il rouge ?

Non. Il n'y a pas de cascade : seul un <Text> parent transmet son style à un <Text> enfant.

Une interface responsive

Du téléphone à l'écran de bureau

Pas de media queries : un hook


import { useWindowDimensions } from "react-native";

// Nombre de colonnes selon la largeur de la fenêtre
export function useColumns(): number {
  const { width } = useWindowDimensions();
  if (width >= 1024) return 3;
  if (width >= 600) return 2;
  return 1;
}
  • StyleSheet ne connaît pas les media queries du CSS
  • useWindowDimensions() renvoie la taille de la fenêtre et déclenche un nouveau rendu quand elle change (rotation, redimensionnement)
  • L'ancienne API Dimensions.get() ne se met pas à jour toute seule : préférez le hook

Une grille sur le web, une liste sur mobile


export default function CatalogScreen() {
  const columns = useColumns();
  // …
  return (
    <View style={styles.container}>
      <FlatList
        key={columns}
        numColumns={columns}
        data={visibleStays}
        keyExtractor={(stay) => stay.id}
        renderItem={renderStay}
      />
    </View>
  );
}
  • numColumns transforme la liste en grille
  • FlatList refuse de changer de nombre de colonnes à chaud. Changer sa key force un nouveau montage
  • Sur le conteneur, maxWidth: 1100 et alignSelf: "center" évitent une ligne de 2 500 px sur un grand écran

Adapter le code à la plateforme


import { Platform } from "react-native";

const label = Platform.select({
  ios: "iPhone",
  android: "Android",
  web: "navigateur",
  default: "autre",
});

if (Platform.OS === "web") { /* … */ }
  • Platform.OS vaut "ios", "android" ou "web"
  • Pour un composant très différent, créez deux fichiers : map.tsx et map.web.tsx. Le bon est choisi à la compilation
  • Utilisez-les avec parcimonie. Le but reste un seul code

Les zones sûres de l'écran


import { SafeAreaView } from "react-native-safe-area-context";

export default function PrimitivesScreen() {
  return (
    <SafeAreaView style={{ flex: 1 }}>
      <ScrollView contentContainerStyle={styles.content}>
        {/* … */}
      </ScrollView>
    </SafeAreaView>
  );
}
  • Encoche, île dynamique, barre de gestes : certaines zones de l'écran ne doivent pas recevoir de contenu
  • SafeAreaView ajoute les marges nécessaires
  • Importez-la depuis react-native-safe-area-context (déjà installé par Expo)
Quand un écran a un en-tête de navigation (Stack), l'en-tête gère déjà la zone du haut.

À retenir

  • React Native affiche de vraies vues natives. React Native for Web les traduit en DOM
  • Expo crée, lance et teste le projet. Expo Router associe chaque fichier de src/app/ à un écran
  • Tout texte est dans un <Text>. Les styles sont des objets, sans cascade
  • Flexbox est partout, en colonne par défaut
  • Le responsive passe par useWindowDimensions() et des points de rupture
  • TypeScript décrit vos données et vos props, et vérifie avant l'exécution
