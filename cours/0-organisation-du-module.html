Le module

Organisation du module

Une base de code, trois plateformes

iOS

De vrais composants natifs, affichés par le système du téléphone

Android

Le même code TypeScript, sans réécrire l'application en Kotlin

Web

React Native for Web transforme <View> en <div> dans le navigateur
  • Vous connaissez React. Vous allez réutiliser vos réflexes : composants, props, état, hooks
  • Ce qui change : pas de HTML ni de CSS, des contraintes mobiles (tactile, taille d'écran, réseau, cycle de vie)
  • Exemple en production : l'application Bluesky, écrite avec React Native et Expo, tourne sur iOS, Android et le web
Demander qui a déjà fait du React Native, du Flutter ou du natif. Le code de Bluesky est public : c'est une bonne référence d'architecture.

Objectifs du module

À la fin du module, vous serez capables de :

  • Maîtriser React Native et son extension web pour concevoir une application performante à partir d'une base de code unique
  • Structurer votre application selon le pattern MVC : composants d'affichage, hooks et services pour la logique, modèles de données typés
  • Concevoir des interfaces réactives et fluides avec les composants natifs, le rendu web et Flexbox
  • Gérer le cycle de vie, la navigation et la persistance des données de manière unifiée entre le navigateur et le mobile

Programme

Cours 1 · Fondations

Architecture, React Native for Web, Expo, TypeScript, composants primitifs, Flexbox et responsive

Cours 2 · Architecture

Pattern MVC dans React, hooks personnalisés, services, modèles typés, état global avec Context

Cours 3 · Navigation

Expo Router (pile, onglets, URL, liens profonds), cycle de vie, listes volumineuses

Cours 4 · Persistance

Firebase : authentification, base Firestore, temps réel et règles de sécurité. Mise en production
Environ un tiers de théorie et deux tiers de pratique. Chaque notion est appliquée dans un TP le jour même.

Sur votre ordinateur

Rendu final et démo

Ce que votre application doit contenir

Obligatoire

  • Au moins 4 écrans, avec des onglets, une pile et une route dynamique
  • L'URL du navigateur suit la navigation sur le web
  • Un catalogue responsive : grille sur ordinateur, liste sur mobile, avec des filtres
  • Une API publique consommée avec fetch()
  • Firebase : authentification et 2 CRUD
  • Une architecture MVC en TypeScript
  • Un README complet

Valorisé

  • Une API native : caméra, localisation, notifications…
  • Des animations soignées
  • Un cache ou un mode hors ligne
  • Des tests automatisés
  • Une version web déployée en ligne

CC1 : refactoring et portabilité web

  • Vous recevez une petite application React Native mal structurée : elle est pensée uniquement pour le mobile et sa logique est écrite au milieu des composants
  • Votre mission : appliquer le pattern MVC (logique dans des hooks et des services, composants d'affichage purs) et la rendre impeccable sur le web
  • Individuel, 1h30, sur votre machine, sans IA. La documentation officielle est autorisée
  • Rendu à la fin du créneau : le lien de votre dépôt par e-mail
Critères : séparation stricte des responsabilités, aucun bug d'affichage sur le web, propreté du code.

  • 5 min : démonstration sur le web et sur mobile
  • 3 min : questions, au moins une par membre du groupe
  • Rendu : dernier commit poussé la veille à 23h59

Examen écrit · 45 min

  • À la fin de la séance, après les démos
  • Questions ouvertes sur l'ensemble des cours
  • Plusieurs questions portent sur des extraits de code à lire ou à corriger

L'IA générative : autorisée, à une condition

  • ChatGPT, Claude, Copilot… sont autorisés pour les TP et le projet
  • Vous devez comprendre votre code de bout en bout. Chaque membre du groupe doit pouvoir expliquer chaque partie
  • Déclarez votre usage dans le README : quels outils, pour quoi faire
  • Les questions de la démo vérifient cette compréhension. Une fonctionnalité non expliquée n'est pas comptée
  • Le CC1 et l'examen écrit se font sans IA
  • Le plagiat et la triche entraînent un 0 à l'épreuve concernée
Conseil : utilisez l'IA comme un tuteur (expliquer une erreur, relire votre code), pas comme un auteur.
